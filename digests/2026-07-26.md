Progress Advantage (0.93) is the most structurally important finding of the day. It provides the formal theoretical grounding for TRACE (Jul 25): TRACE's turn-level state values (log π_ref / π_ref_old) are an approximation of the progress advantage (log π_RL/π_ref). More precisely, Progress Advantage proves that after convergence, the RL-trained policy's log-ratio against the reference is the optimal advantage — which means any method that uses the reference model's log-probs as a signal (TRACE, Distilled RL, APO's KL terms) is implicitly computing a variant of the optimal advantage function. The paper's practical applications (test-time scaling, uncertainty quantification, failure attribution) are immediately usable without any additional training: any lab that has run GRPO/PPO post-training already has the progress advantage for free. The finding that it outperforms trained reward models without task-specific training is particularly significant given the persistent difficulty of reward model training for agentic tasks (confirmed empty via six+ searches, Gap #4).

PRPO (0.88) is the most important VLM-specific paper in weeks. The RVD metric addresses a failure mode specific to multimodal RL that no prior vault paper has targeted: visually ungrounded tokens receiving the same gradient signal as visually pivotal tokens. GRAIL (today, 0.80) uses gradient saliency for token-level reweighting in LLMs but is not multimodal; OPPO (Jul 24) uses Bayesian recursion but is text-only; PRPO's RVD is the first signal computed from visual perturbation sensitivity rather than gradient or probability information. The +23.3%/+21.1% gains across seven benchmarks are among the largest VLM RL improvements in the vault. Notably, PRPO does not require a dedicated VLM reward model (Gap #4) — it derives the credit signal intrinsically from the model's visual sensitivity, suggesting that the gap between VLM RL and text RL credit assignment can be closed without additional model training.

Harness Design (0.87) provides the mechanistic study that OpenForgeRL (Jul 24) identified as missing: why do some harness architectures resist RL improvement? The answer is not about algorithm or reward signal but about the observation space and tool API exposed to the model. When the harness provides insufficient auxiliary information or describes tools inadequately, post-training cannot compensate — and this failure is exacerbated under OOD tool shifts. This closes Gap #15 (harness choice and RL trainability) more fully than PATS (Jul 25): PATS shows that adaptive training-context scaffolding compensates for a weak policy; Harness Design shows that harness-aware design is the upstream intervention that makes post-training effective in the first place.

CompactionRL (0.85) addresses the context window constraint directly within the RL loop, which is a different strategy than TRACE's turn-level credit (which avoids the need for long trajectories) or PATS's scaffold (which reduces prompt tokens). The cross-trajectory GAE is the key technical innovation: it ensures that the credit assignment signal propagates correctly across the compaction boundary, where a long trajectory is compressed into a summary before continuation. This is a new credit assignment primitive not present in prior vault papers. The GLM-5.2 production deployment is notable — CompactionRL is apparently already in use at scale.

STAPO (0.82) partially closes Gap #12 (entropy as structural signal beyond BPO). BPO uses entropy-weighted branching to allocate rollout budget to high-uncertainty decision points; STAPO uses normalized entropy to allocate gradient budget to high-uncertainty (neglect-prone) steps. Both use entropy as a structural signal, but at different levels: BPO is a training algorithm that changes which trajectories get sampled; STAPO is a credit assignment method that changes which tokens get larger gradient updates within a fixed trajectory. The normalized entropy formulation (deviation from the agent's own average, not absolute entropy) is more informative than raw Shannon entropy because it accounts for the agent's calibration at each state type — a step is flagged as neglect-prone only if its entropy is high relative to the agent's typical behavior in similar states, not just because the state is intrinsically ambiguous.

**New finding — Progress Advantage as theoretical foundation for reference-model-based methods:** Progress Advantage (log π_RL/π_ref = optimal advantage) retroactively explains TRACE (turn-level log-ratio state values), APO's KL divergence terms (which are log-ratio-based), Distilled RL (reverse IS using the reference), and OPPO's Bayesian recursion (which approximates the same quantity). These papers can now be understood as approximations or variants of the optimal advantage function derivation from Progress Advantage.
